Существующие JSON-файлы не переписывались.

## Автоматические проверки

```bash
python tools/validate_game_spec.py --ready
python tools/validate_workflow_state.py --ready
python tools/validate_architecture.py
python tools/validate_project.py
godot --headless --path . --editor --quit
godot --headless --path . --script game/bootstrap/app/tests/run_lighting_tests.gd
godot --headless --path . --quit-after 180
```

Явный коэффициент 1.0 также сохраняется при JSON round-trip. Тесты освещения работают с реальными сценами лампы и приложения и существующей сериализацией планировщика. Проверяют также нулевую энергию, сцену без metadata, карту без поля энергии и изменение игровых ambient-настроек между сессиями. Набор не сохраняет карты на диск и не переписывает авторскую сцену.

Локально Godot 4.5.2: тесты освещения — 0 failures; основная сцена отработала по 180 headless-кадров с forward_plus и gl_compatibility без SCRIPT ERROR/ERROR. Editor import завершился 0, но содержит прежние ошибки отсутствующих FBX-текстур palette1.png/couches.png, поэтому импорт не считается чистым. Readiness/workflow/architecture проходят. После коррекции CI планировщик разделён по обязанностям (planning_mode.gd: 428 строк); полный validate_project.py проходит без исключений лимита. Подробности: PLANNER_REFACTOR_QA.md.

## Визуальная приёмка — НЕ ВЫПОЛНЕНА

В окружении нет графического дисплея/GPU и настроенных Windows/Web export presets. Кадры до/после, графический Forward+/Compatibility и производительность двух сборок не проверены. Headless использует dummy rendering и подтверждает только загрузку/логику, даже при указании rendering-method. Целевая Godot 4.7.2 не проверена.

1. В Windows Forward+ и desktop Web Compatibility открыть один и тот же участок и зафиксировать камеру, разрешение, набор объектов и состояние боя. Снять игровой кадр с исходного коммита 7712a3e2d2f3fa70322f8f1e0a7637955d433ef3 и кадр с правками. Сравнить отдельно при отключённом SSR/GI.
2. Проверить стены, мебель и силуэт вне пятна; холодные затенённые зоны; преобладание тёплых верхних ламп; цвет и детали пола внутри пятен. Не оценивать это по редакторской подсветке 0.38.
3. Войти/выйти пять раз, переключая «Игровое освещение» / «Подсветка редактора». Игровой preview, выход и перезапуск должны возвращать исходный ambient 0.22 без изменения цвета.
4. Для постоянной и мерцающей лампы изменить авторскую яркость, сохранить карту и загрузить пять раз. Авторская энергия и базовая эффективная мощность должны оставаться одинаковыми. Повторить с энергией 0, Undo и Duplicate.
5. Записать одинаковый 60-секундный маршрут до/после в обеих сборках: устройство, разрешение, renderer, средний FPS, p95 frame time и CPU/GPU time. Цель 60 FPS; добавление теней отложено до этих измерений.
6. Для изолированного A/B: отключить ambient только через energy=0; отдельно вернуть multiplier=1.0. Экспозицию, материалы и камеру оставить прежними.

Следующее действие: визуальная приёмка и измерение 60 FPS на указанном одинаковом участке; только затем корректировать подтверждённый проблемный источник одним параметром за проход.
