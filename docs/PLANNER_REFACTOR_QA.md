# Разделение планировщика после ошибки CI

30.09.2026: job validate в run 36773694786 для PR #17 прошёл validate_architecture.py, но остановился в validate_source_size.py: planning_mode.gd содержал 1627 строк при лимите 600.

## Решение

Существующий bootstrap.app разделён по причинам изменения, без новой архитектурной границы:

| Файл | Ответственность | Строк |
|---|---|---:|
| planning_mode.gd | Владение сессией планирования, lifecycle, input и композиция | 428 |
| planning_catalog.gd | Каталог, палитра и создание выбранного ассета | 141 |
| planning_view.gd | Контролы, сетка, выделение и обратная связь освещения | 245 |
| planning_objects.gd | Размещение, picking, изменение и удаление объектов | 405 |
| planning_geometry.gd | Лучи камеры, привязка к сетке/поверхности и геометрия размещения | 207 |
| planning_storage.gd | Сериализация карт, загрузка и экспорт авторской сцены | 302 |

Состояние сессии остаётся у planning_mode внутри bootstrap.app; компоненты получают явный локальный контекст. Существующий фасад сохраняет команды/запросы, используемые desk setup, history и тестами. Ни module dependencies, ни публичные межмодульные API, ни сохранения не менялись. Каталог объектов, камера, освещение и пользовательский ввод сохраняют прежнее поведение.

Обзор файлов выше порога 300: mode отвечает за жизненный цикл одного режима и его композицию; objects — за команды над планируемыми объектами и их undo-транзакциями; storage — за единый layout DTO и способы его сохранения/загрузки. Разделять их дальше в этой коррекции не требуется: жёсткий лимит соблюдён, отдельные функции не превышают 100 строк. Предупреждения 300/50 строк остаются видимыми; исключения лимита и ослабление CI не добавлялись.

- Godot 4.5.2 run_planning_tests.gd — 0 failures: реальные сигналы палитры, повторное размещение, player spawn, горячие клавиши яркости/поворота/перемещения/удаления, Undo, ограничения камеры, grid, имя карты и JSON round-trip.
