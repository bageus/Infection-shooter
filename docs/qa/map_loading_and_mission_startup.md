# Безопасная загрузка карты и запуск миссии — 09.10.2026

Инкремент T002 по двум следующим пунктам аудита. Владельцы состояния остаются
в bootstrap.app; публичные API других модулей, DTO карты v1–v8, зависимости,
баланс и архитектурная policy не меняются. Исключений нет.

## Карта

Прежний `_apply_layout_data` очищал локацию и историю до чтения массива объектов.
Теперь `planning_layout_validator` проверяет контейнер, версию, тип каждой записи,
путь сцены, конечность чисел, ненулевой масштаб и структуры optional properties.
`planning_layout_loader` создаёт объекты вне дерева без привязки к игровой сцене.
Только после успешной подготовки всей карты очищается старая локация и выполняются
привязки, восстановление свойств, игрока и объектов. При ошибке подготовленные
узлы освобождаются, а локация, выделение, spawn transform и undo не меняются.

Явный `objects: []` остаётся допустимой пустой картой. Частично отсутствующие
ассеты пропускаются с прежним отчётом loaded/skipped/missing; непустая карта,
из которой нельзя загрузить ни одного объекта или игрока, отклоняется.
Старые aliases сохраняются. История правок очищается через typed array.clear:
прежний Object.set с нетипизированным [] не очищал Array[Dictionary].

Загрузка и материализация вынесены из planning_objects в отдельный компонент.
planning_objects сохраняет команды размещения и редактирования; planning_storage
хранит чтение файлов и authored snapshot; planning_mode и main остаются локальной
композицией. Файлы выше 300 строк рассмотрены: в них добавлены только делегирование
и режим отложенного чтения; новых несвязанных обязанностей не добавлено.

## Миссия

Старт из меню и restart используют один `mission_loader`, с loading overlay,
поэтапным прогрессом и возвратом после ошибки. Повторные команды блокируются.
До завершения предыдущая сцена остаётся current_scene; симуляция приостановлена.
Перед фоновой загрузкой scene_resource_preparation обходит зависимости сцен и
компилирует их скрипты в основном потоке, удерживая ссылки до завершения операции.
Это обход нестабильного worker-side GDScript preload на Godot 4.7.2: прямые
threaded probes давали refcount=0 warnings, промежуточные проверки — stalls.
Основной PackedScene и уникальные сцены карты затем читаются через threaded ResourceLoader.
Пути model_path, сохранённые строками внутри PackedScene, также подгружаются заранее.
Ресурсы удерживаются до конца подготовки, чтобы обычное load в _ready использовало
кэш. load_threaded_get вызывается только после THREAD_LOAD_LOADED.

Создание и добавление узлов происходят на основном потоке, с передачей управления
между кадрами через 16 объектов или после 4 мс работы. Это бюджет порции, а не
жёсткий предел кадра: instantiate/один _ready не прерываются внутри операции.
Карта загружается отдельно от _ready основной сцены. Прямое инстанцирование main
в существующих тестах сохраняет прежний синхронный режим по умолчанию.

После успешной подготовки применяются authored snapshot, физика и настройки;
только затем активируется новая сцена и освобождается предыдущая. Ошибка карты
освобождает pending mission и сохраняет прежнюю сцену, паузу и активную камеру.

## Проверки

Godot 4.7.2 headless:

- Новый layout_loading проверяет 16 случаев некорректных данных, ошибку из файла,
  не-Node3D после корректной записи, сохранность объектов/undo/selection/spawn,
  partial missing, empty layout, порядок и передачу управления между кадрами.
- Новый mission_loading проверяет повреждённую карту, видимый overlay до работы,
  повторный start, retry, завершение всех записей до активации, ошибку restart
  с сохранением прежней камеры и успешный restart с удалением старой сцены.
- Menu, planning_mode, planner_persistence, planner_extension, display_planner,
  world_bindings и layout_bake пройдены. Assertions menu сохранены; фиксированное
  ожидание двух кадров заменено ожиданием завершения с прежними проверками сцены.
- Полная поставляемая карта содержит 1034 объекта; отдельный запуск загрузился
  примерно за 10,5 с на этом headless окружении, с прогрессом по кадрам. Это не
  сравнение с исходной скоростью и не гарантия времени на другом компьютере.
- Новые тесты включены в Mission CI; project/resource/import gates, editor import
  и обычный main smoke проверены.

Один ранний параллельный тяжёлый запуск и один промежуточный serial menu запуск
достигли timeout; при завершении прерванной загрузки появились preload errors.
Диагностический полный запуск и финальные последовательные regression suites
прошли. Native Windows/Web интерактивная приёмка остаётся ручной.

В ранних threaded headless запусках при выходе появлялись RefCounted с refcount=0.
Минимальный probe load_threaded_request/get без нашего загрузчика воспроизводил
это предупреждение; синхронный probe — нет. После предварительной компиляции
скриптов сцены и map assets в основном потоке финальные mission_loading и menu
прошли без ObjectDB/RID warning и без preload errors. Существующая upstream issue
https://github.com/godotengine/godot/issues/120661 описывает похожее поведение,
но тождество причин не доказано (у нас use_sub_threads=false). Backlog хранит
результат и необходимость проверить обход на native Windows/Web; изменение
версии движка и зависимостей не входит в этот инкремент.

Откат: revert коммита; форматы и пути исходных карт не менялись.
