# ADR-0047: Сохраняемый бюджет мутаций, превью антидота и ампула на выходе

Status: accepted; Date: 2026-10-15; Owner: bageus.

## Решения владельца

Вариант B: бюджет по максимальной достигнутой мутации (до16), возврат очков за забытые незакреплённые узлы, прежние требования текущей мутации/стабильности и смысл закрепления. Ни повторное поглощение мутагена после антидота, ни компенсация ампул не создают новые очки сверх этого максимума. Порог90 для поздних веток сохраняется. Обычный антидот предупреждает о забытых и неактивных узлах и показывает будущие очки; отмена бесплатна. Аварийное применение при срыве/эскалации мгновенно, с прежними -10 мутации и завершением текущего срыва. Старый тест запрета во время срыва заменён тестом нового явно согласованного поведения.

Контрольных сохранений/перехода кампании в текущем прототипе нет, кнопка Continue отключена. После уточнения владелец выбрал существующий выход с этажа как временную точку компенсации. При begin_control_level задаётся стабильный ID авторской сцены, любая собранная на этом этаже ампула помечает collection; complete_control_level компенсирует только не собранную, один раз на ID, не принимает чужой ID. Bootstrap вызывает после постановки результата на паузу, чтобы выдача не открывала дерево поверх результата. Новый забег по-прежнему начинает новое состояние; долговременные сохранения кампании этим PR не добавляются.

## Владельцы и контракты

MutationTree владеет peak_mutation. Runtime обновляет его при изменении мутации, включая значение до антидота. ControlProgress владеет локальной историей уровня и строит чистый antidote_preview DTOv1 через копию learned/locked и тот же reconcile, без дублирования правил потерь в UI. PlayerAntidote владеет pending request и проверяет неизменность превью/наличие дозы перед исполнением; доза расходуется ровно один раз. Публичные сигнал antidote_confirmation_requested, confirm_antidote/cancel_antidote описаны features.player/module.json; preview/begin/complete — features.infection/module.json. Новых dependency edges или глобального состояния нет.

CanvasLayer подтверждения принадлежит bootstrap и работает во время паузы, отмена/подтверждение возвращают предыдущую паузу, в том числе поверх дерева. Подписи, названия веток, все35 имён/описаний навыков, карточки и hotbar берутся из assets/interface/translations.json для ru/en; переключение языка обновляет уже созданное дерево. Метка Control threshold / Порог контроля.

## Альтернативы, миграция и откат

Вариант A сохраняет сжимаемый бюджет, C снижает пороги — владелец выбрал B. Пожизненно активные навыки изменили бы закрепление/риск — не вводятся. Новая система кампании не создаётся ради одной компенсации. Существующих persisted gameplay snapshots здесь нет, их форматы не меняются; preview — новая версия1 временного DTO. Новые команды/сигнал аддитивны, старые runtime.use_antidote и player.use_antidote остаются. Откат revert PR; профили раскладки/настроек прежние.

## Проверка

Расширен infection run_tests: retained/refund/пять циклов без фарма/16cap, чистый preview, emergency control-loss, collection/exit/mismatch/repeated id/95cap. Новый progression_ui в CI: реальный player, подтверждение/отмена/устаревшее превью/повторное подтверждение/emergency, RU/EN ключи всех навыков и переключение открытого дерева. Menu integration проверяет действительный _end_run и отсутствие дублирования ампулы. UI sound проверяет локализованный текст вместо прежнего фиксированного английского. Обязательные валидаторы, import и связанные runtime-наборы выполняются до публикации. Прослушивание и ручная Windows/Web приёмка остаются отдельно.
