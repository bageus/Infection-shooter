# ADR-0035: Очередь поиска пути и выделение состояния разрушений

- Status: accepted
- Date: 2026-10-06
- Owners: bageus
- Related modules: bootstrap.app, features.infected, features.combat, presentation.office_floor

## Context

Аудит main b332e32 выявил повторную привязку частиц, полную пересборку силуэтов
при изменении одного объекта, индивидуальные синхронные A* врагов, повторный
пересчёт оружия и правила разрушений внутри presentation. Владелец поручил
реализовать предложенную последовательность: «приступай по порядку».

## Decision

Bootstrap создаёт одну public/chase_search_budget.gd в контейнере миссии и
внедряет её через configure_chase_budget(budget). features.infected владеет
FIFO слабых запросов и выполняет не более двух полных A* за физический кадр.
Путь остаётся ограничен 192 раскрытиями; проверки прямой видимости и коллизий
сохраняются. Пока запрос ожидает, враг использует последний проверенный путь
либо стоит, если пути ещё нет. Изолированная сцена без очереди сохраняет
синхронный поиск. Очередь не глобальная и останавливается вместе с миссией.

Состояние здоровья и переходов environment_prop переносится в engine-light
публичный объект features.combat. presentation по-прежнему владеет моделями,
коллизиями, физической реакцией и отображением стадий. Зависимость office_floor
на combat уже существует; направления слоёв, map DTO v8 и баланс прежние.
Изменение владельца состояния отражается в manifests и ARCHITECTURE.md.

## Alternatives considered

### Глобальная очередь или статический счётчик кадра

Проще внедрить, но смешивает несколько миссий и нарушает явное владение состоянием.

### Немедленная замена A* на NavigationServer

Требует новой навигационной геометрии и пересчёта после редактирования/разрушений.
Для текущего результата достаточно ограничить существующий проверенный алгоритм.

### Полное переписывание окружения

Не нужно для отделения правил здоровья и переходов. Физика, модели и эффекты
сохраняют существующие точки интеграции.

## Consequences

- Пики полного поиска ограничены числом запросов на кадр, а не количеством врагов.
- Первая реакция на сложный путь может задержаться при длинной очереди.
- Выделенные правила разрушения можно проверять без загрузки моделей.
- Не обещается конкретное увеличение FPS без замеров на целевом устройстве.

## Migration plan

1. Однократная привязка частиц и частичное обновление силуэтов.
2. Аддитивный chase_budget_v1 и очередь с прежним standalone-поведением.
3. Обновление оружия по изменениям, затем удаление внутренних неиспользуемых функций.
4. Выделение состояния разрушений с сохранением внешних методов сцен и map DTO.
5. Локальные gates и полный существующий CI, включая оба renderer.

## Rollback plan

Отменить соответствующий отдельный коммит. При откате очереди вернуть синхронный
вызов A*. При откате разрушений вернуть прежнее состояние environment_prop.
Пользовательские сохранения и ресурсы не требуют миграции.

## Validation

Regression: дедупликация привязок, сохранение экземпляров силуэтов при спавне,
detach/reattach стен, ограничение и обслуживание FIFO, истечение баффов,
неизменность последовательности стадий разрушения. Project gates обязательны;
рендер и Godot runtime проверяются CI, локально движок отсутствует.

## Approval

Владелец bageus 06.10.2026 явно поручил выполнить предложенные оптимизации по порядку.
Публикация выполняется в отдельной ветке/PR; автоматическое слияние не включается.
