# ADR-0065: панели и палитры планировщика

Статус: принято прямым запросом владельца 24.10.2026.

## Решение

bootstrap.app сохраняет владение планировщиком и UI. Приватный
planning_hud_layout собирает уже подключённые виджеты: правая единая панель
с вкладками «Основная»/«Конструктор», сворачиванием и независимой ручкой
возврата; слева фиксированная ширина, сетка вкладок; название/координаты
выделенного объекта в отдельной панели под Undo/Duplicate. planning_controls
остаётся адаптером команд. Новые обязанности компоновки и фильтров вынесены
из файла >300 строк. main/planning_mode/objects/geometry (>300) получают
только wiring, обновление представления и проверку ввода/выбора; дальнейшее
расширение их ответственности не требуется.

В «Основная»: Map/Layout Save, Load, настройки света/тумана, автоматических
выключателей/пожарных кнопок, следов поверхностей, вид сверху, Clear/Exit.
В «Конструктор»: цепочка карт и входы. Вид сверху доступен любой палитре.
Items/Weapons — вкладки; Biomass отдельно; Blood переименована в Decals,
с категориями кровь/стекло/пол/стены и фильтрами напольных материалов.

presentation.office_floor предоставляет read-only public/surface_decor_catalog.gd
(entries и texture_entry). Используются существующие атласы и публичная сцена
blood_decal: тот же configure_blood, размер, поверхность, привязка, Undo,
JSON и PackedScene. В существующей строке texture добавляется пространство
имён surface:<kind>:<zero-based-frame>. Старые blood/biomass id не меняются;
версия карты8 и структура DTO прежние. Каталог не декодирует все атласы
на старте: AtlasTexture ссылается на исходную импортированную текстуру.
Новые кадры не добавляются в случайный игровой blood catalogue.

Отключённая darkness_zone прекращает _process, скрывает Overlay и выставляет
transient planning_pick_disabled. Bootstrap исключает её из hit-test и
снимает прежнее выделение зоны при выключении. Это устраняет специальный
fallback AABB невидимого тумана. У зоны изначально нет физических коллайдеров;
отключённая зона не блокирует физический луч. Авторские параметры и reveal
сохраняются для включения/сохранения карты. Нет удаления пользовательских зон.

Владельцы, зависимости, Autoload, policy и budgets игровых следов прежние.
Исключений архитектуры нет. Ручные декали — авторские размещённые объекты,
как прежняя кровь, не новые игровые per-hit объекты.

## Альтернативы

- Одна длинная колонка: плохо управляется и закрывает сцену.
- Удаление зон при выключении: теряется авторская карта и восстановление.
- Отдельный save DTO/сцена для каждого материала: дублирует уже работающие
  размещение/привязку и миграцию без необходимости.

## Миграция и откат

Старые карты читаются без преобразования. Новый код читает старые texture id.
Для отката UI вернуть commit; карты с surface: id требуют текущего renderer
(старый код не знает новые картинки). При откате контента удалить только
добавленные вручную surface: records, сохранив оригинал карты. Никакого
автоматического изменения/перезаписи файлов при открытии вкладки нет.

## Проверка

run_planner_hud_tests: вкладки, фиксированная ширина, hide/restore/input,
название/панель выделения, отключённый fog hit-test, разделение биомассы,
каждый материал, atlas pixels, JSON/PackedScene roundtrip.
Существующие planning_mode, biomass_planner, planner_fog, planner_loot,
planner_light_view, global_lighting дополняют регрессионный прогон.
