# ADR-0019: Многосценовые разрушаемые GLB

- Status: accepted
- Date: 2026-10-04
- Owner: bageus
- Modules: presentation.office_floor, addons/staged_glb_import (вне модулей, инструмент импорта)

## Контекст

Владелец перевёл 58 моделей окружения в новый формат разрушения: каждая
стадия — отдельная glTF-сцена одного GLB (Intact, Power_Off, LargeParts,
SmallFragments / JaggedFragments; у растений PlantDestroyed, DamageParts,
PotFragments; у стойки ресепшена DamageReady). Godot импортирует только сцену
по умолчанию, поэтому стадии пропали, а шкафы, столы, техника, коробки,
книги и растения перестали разрушаться (упали тесты debris и world bindings).

## Решение

- Плагин редактора `addons/staged_glb_import` регистрирует
  GLTFDocumentExtension: при импорте каждая непустая сцена GLB становится
  группой с именем сцены. Сцена по умолчанию видима, остальные получают
  нулевой масштаб — прежнее соглашение о скрытых стадиях
  (environment_damage.gd возвращает масштаб при показе). Исходные GLB не
  меняются. GLB с одной непустой сценой импортируются как раньше.
- При первом запуске редактора с плагином эти модели один раз
  переимпортируются (метка в метаданных проекта), чтобы локальный кэш
  обновился без ручного Reimport. Холодный импорт в CI проверен.
- environment_prop: стадии SmallFragments, JaggedFragments, PlantDestroyed,
  PotFragments; часть стадии из одного куска (упавший горшок) при попадании
  разбивается на всю следующую стадию; DamageReady — разрушение на месте:
  ядро стойки остаётся, при попаданиях откалываются ближайшие Facade_Chip.
  Встраиваемые полки добавляются только старым книжным шкафам.

## Последствия

- Новый набор `run_staged_glb_tests.gd` в CI.
- Новые модели в этом формате работают без кода, если их стадии названы как
  выше; новые имена стадий добавляются в `_discover_stages`.

## Уточнение разрушения по запросу владельца — 25.10.2026

Стеклянные перегородки также передают фактический тип попадания в private shard spawning. Обычные пули больше не запускают взрывное вращение, подброс и повторное опрокидывание обломков. Эксплозивная реакция сохраняется при GRENADE, включая последующий split. Авторские детали получают ориентированные по мешу box-коллизии вместо раздутого world AABB; bounce снижен до0.02. При дроблении движущейся детали fine stage переносится из исходного authored frame в её текущий mesh frame и наследует её движение. Числовые Blender-суффиксы вроде .001 не мешают сопоставлению; неизменённая одиночная часть следующей стадии не выдаётся за дробление, лимит32 больше не обрезает авторскую стадию. Общий mission-local lifecycle/burst budget сохраняется. Старый staged_table также различает bullet collapse и grenade scatter, включая оставшиеся ножки и предметы на столешнице. HP/owner/public signatures/DTO прежние. Функции spawn/continuation остаются private внутри office_floor. Evidence: docs/qa/prop_destruction_reactions.md.
