# ADR-0063: Переключатель тумана войны в планировщике

- Status: accepted
- Date: 2026-10-24
- Owners: bootstrap.app, presentation.office_floor
- Related modules: bootstrap.app → presentation.office_floor (существующее ребро)

## Контекст

Владелец попросил включать и отключать туман войны (затемнение) из настроек
планировщика. Удаление зон или изменение их непрозрачности испортило бы карту.

## Решение

Bootstrap хранит boolean `view/fog_of_war` в отдельном локальном
`user://planner_settings.cfg`, по умолчанию true. Private `planning_fog.gd`
создаёт переключатель под локальными лампами, применяет значение к текущим
зонам и через node_added — к новым экземплярам публичной сцены darkness_zone.
Уточнение владельца25.10.2026 заменяет исходное поведение: preference действует
только при видимом PlanningUI. При выходе в игру все зоны снова получают true;
поздно загруженные зоны тоже получают true. Возврат в планировщик применяет
сохранённый выбор предпросмотра. visibility_changed и node_added не требуют
покадрового обхода. Сохраняется только выбор предпросмотра, при переключении.

Публичная сцена `public/props/darkness_zone.tscn` получает additive метод
`set_fog_of_war_enabled(bool)` (`fog_of_war_v1`). Зона сохраняет владение
исследованием и портальными проёмами. Выключение скрывает только Overlay
и приостанавливает расчёт исследования; включение сохраняет reveal/fade.
Исходная видимость корня, поля карты и параметры материала не меняются.
Разрешение transient, не экспортируется и не добавляется в карту.
Новых владельцев, зависимостей, Autoload и плагинов нет.

## Альтернативы

1. Удалять зоны или записывать darkness=0: теряются авторские параметры.
2. Скрывать корневые узлы: влияет на выделение/сохранение и не останавливает
   исследование выключенного тумана.
3. Глобальное отключение в игре: заменено режимом только предпросмотра
   по прямому уточнению владельца25.10.2026.

## Последствия и риски

Один сигнал node_added на сцену; нет нового покадрового обхода зон.
Отложенный вызов проверяет WeakRef и queued-for-deletion. Подписка снимается
при выходе helper из дерева. Неизвестный тип preference даёт default true.
Риск восстановления тумана обновлением комнаты закрыт ранним gate в _process
и повторным применением gate при пересоздании Overlay.

## Миграция и откат

Старые карты и gameplay saves совместимы; отсутствующий cfg означает true.
Для отката revert PR: старый код игнорирует отдельный cfg, зоны остаются целыми.

## Проверки

`run_planner_fog_tests`: переключение, pause, сохранение/повторная загрузка,
ошибочный тип, зоны после загрузки, пересборка материала, сохранённое исследование
и авторская видимость. Существующий run_darkness_room_tests проверяет комнаты.
Общие project gates и CI регистрация. Ручная приёмка UI остаётся отдельной.

## Одобрение

Прямой запрос владельца 24.10.2026: добавить переключатель в настройках режима
планирования и создать PR. Additive метод необходим для этого переключателя;
распределение состояния и архитектурные рёбра сохраняются.


## Дополнение: палитра и группы затемнения

По дополнительному запросу владельца от 24.10.2026 bootstrap расширяет
planning_room_options: высота в метрах и существующий room_id доступны
для палитры/превью и выбранной зоны обоих типов. Поля выбранной зоны не
переписывают defaults палитры. Список групп текущей миссии исключает preview,
показывает число зон и сохраняет выбранную группу при обновлении.

Private planning_darkness_groups рисует временные голубые плоскости и контуры
в отдельном контейнере; они видны при выключенном тумане, следуют за transform
и размером зоны, не получают owner/коллизий/теней и очищаются при выходе.
Membership обновляется не чаще четырёх раз в секунду, вне планировщика обхода
нет; покадрово обновляются только маркеры выбранной группы. Выбор зоны также
показывает её группу. Geometry использует авторский размер тёмной зоны для
picking независимо от видимости Overlay.

Private planning_darkness_config переносит существующие size/darkness/
permanent/room_id при дублировании, Undo и scene bake. Высота уже входит в
transform/JSON y; room_id уже входит в JSON DTO. Новых persisted полей нет.
Сцена больше не теряет группу и тип зоны при Bake. Публичных методов/рёбер
не добавляется. planning_controls и planning_geometry остаются адаптерами
существующих UI/геометрических операций; новое состояние/рендер вынесены
в отдельные helpers, архитектурных исключений нет.

Дополнительный runtime suite run_darkness_palette_tests проверяет preview,
новые/выбранные зоны, список/маркеры, выключенный туман, движение/масштаб,
добавление/удаление, Undo, duplicate, JSON и загрузку сохранённого Bake.
