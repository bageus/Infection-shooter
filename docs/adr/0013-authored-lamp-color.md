# ADR-0013: Индивидуальный оттенок ламп в планировщике

- Status: accepted
- Date: 2026-09-30
- Owners: bageus
- Related modules: bootstrap.app, presentation.office_floor

## Context

Владелец запросил оттенок каждой лампы без необходимости искать источник в Remote. Цвет должен сохраняться независимо от производной энергии и общего разрешения локальных ламп.

## Decision

Office_floor владеет авторским RGB цветом в planner_light. Совместимое дополнение публичного контракта сцены planner_light_v1: get_authored_color() -> Color и set_authored_color(Color) -> void; экспортируемый light_color доступен также в Inspector корня лампы. Alpha фиксируется в 1. Старые экземпляры захватывают собственный цвет Light при ready, новые значения применяются через один setter.

Bootstrap controls показывает ColorPickerButton «Оттенок» для выбранной лампы и в настройках новых ламп. Непрерывное изменение в одном открытии picker — одна операция Undo. Objects загружает optional DTO v5 light_color:[r,g,b], storage сохраняет его и авторскую сцену, edit_history переносит цвет при Undo/Delete/Duplicate. Границы модулей и зависимости прежние. RGB не содержит яркость: энергия и мерцание остаются отдельными параметрами.

## Alternatives considered

- Только Remote Inspector: не решает сохранение карт и запрос владельца, отклонено.
- Записывать цвет материалов или общий directional: меняет другие объекты и световую основу, отклонено.
- Новая система профилей/синглтон: для одного поля не нужна, отклонено.

## Consequences

Совместимое поле DTO v5; отсутствие light_color сохраняет исходный цвет сцены. Старый reader игнорирует новое поле, но при пересохранении может его потерять. Новых зависимостей, архитектурных исключений и обработки кадров нет. Production controls = 300 строк; objects выше мягкого порога остаётся компонентом создания/загрузки объектов, добавлены только пять строк обработки локального поля, новая ответственность не возникла.

## Migration plan

Без миграции и массового изменения пользовательских карт. RGB появляется при обычном сохранении. Старые сцены сохраняют per-instance Light color; экспортируемое поле позволяет pack/reload новых сцен.

## Rollback plan

Revert изменения; карты с дополнительным RGB останутся читаемыми прежним reader. Перед rollback сохранить карты с нужным оттенком отдельно, так как старое приложение не редактирует его.

## Validation

Расширенный run_lighting_tests проверяет пять JSON round-trip, старые карты и индивидуальные цвета старых сцен, one-gesture Undo и swatch, Duplicate/Delete Undo, цвет при отключении/восстановлении, неизменную энергию/фазу мерцания, default tint и PackedScene reload. Обязательные gates, импорт и runtime CI. Визуальная проверка picker в Windows/Web остаётся открыта без графического запуска.

## Approval

Прямой запрос владельца: «добавь просто в каждый светильник еще и оттенок». Продолжается ранее разрешённая запись непосредственно в main. Исключений из архитектуры нет.
