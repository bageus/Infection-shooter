# ADR-0011: Явные зависимости объектов миссии

- Status: accepted
- Date: 2026-09-30
- Owner: bageus
- Modules: bootstrap.app, features.combat, features.player, features.infected, presentation.office_floor

## Контекст и разрешение

Владелец прямо поручил реализовать оптимальный вариант устранения оставшихся
обращений к current_scene. Выбран небольшой переход на внедрение конкретных
зависимостей. Это разрешение на изменение перечисленных публичных контрактов;
владельцы игрового состояния, направления слоёв и зависимости модулей прежние.

## Решение и контракты

Bootstrap создаёт MissionObjects (контейнер временных объектов) и ImpactEffects
(существующий бюджет следов combat). WorldBindings связывает только публичные
корни сцен. Каждый корень сам передаёт ссылки своим локальным компонентам;
bootstrap не знает расположения оружия, контроллера двери или стеклянного тела.
Это ограниченный помощник композиции без API поиска сервисов или словаря контекста.

Публичная настройка mission_wiring_v1:

- configure_world(container: Node3D, impacts: Node) -> void;
- configure_weapon_drop(command: Callable) -> void на player; команда принимает
  индекс/позицию и возвращает bool, слот меняется только после успеха;
- configure_player(actor: Node3D) -> void на структурных корнях.

Пуля и граната получают те же ссылки от оружия при создании. Их следы используют
существующий внедрённый бюджет, не создают новый бюджет поиском имени родителя.
Сигнатура public/grenade_explosion.gd теперь имеет контракт v2: два обязательных
дополнительных аргумента container и impacts. Единственный рабочий вызывающий
код мигрирован вместе с контрактом. Гильзы, кровь игрока, индикаторы навыков,
вражеский дроп и эффекты мебели используют контейнер с жизнью миссии.
Каталог планировщика получает конкретный bind_asset Callable и связывает новые
объекты до помещения в дерево, включая загруженные карты и настольные предметы.
Враг, добавленный в Enemies, получает зависимости через существующую точку
bootstrap-связки blood events. Глобальных node_added обработчиков нет.

Дверь получает игрока явно: удалены current_scene, поиск игрока по группе и
устаревшее поле player_path (ни одна сериализованная дверь его не задаёт).
Физические запросы и группы игровых объектов для существующих боевых правил
не мигрируются в этом изменении.

## Отвергнутые варианты

- Глобальный Autoload/реестр контекста вновь скрывал бы зависимости.
- Набор типизированных портов и отдельная фабрика на каждый эффект добавляли бы
  много контрактов без текущей потребности в разных реализациях.
- Замена current_scene цепочками родителей привязывала бы модули к новой иерархии.
- Подписка на каждый новый Node дерева добавляла бы глобальную связь и обработку
  всех частиц/мешей; явные точки композиции и фабрика уже покрывают создание.

## Миграция, размеры и откат

Модели, материалы, освещение, сохранения DTO v5, здоровье, боезапас, вероятности
дропа и баланс не изменены. Новые runtime-ссылки не сериализуются. Изолированные
тестовые сцены должны явно передавать нужные зависимости; без контейнера оружие
отклоняет выстрел без расхода патронов, необязательные эффекты пропускаются.
Существующие тесты контроля и HUD переведены на явные зависимости.
Файлы player_movement/environment_prop/interactive_door/planning_mode уже выше
300 строк: добавлены только точки композиции, основные обязанности сохранены,
лимиты 600/100 не повышены. Последующая декомпозиция не нужна для этой миграции.
Откат: вернуть коммит целиком, включая единственного вызывающего explode v2.
Архитектурных исключений и внешних зависимостей нет.

## Проверка

Архитектурный валидатор запрещает current_scene в рабочем features/presentation;
bootstrap/infrastructure и tests разрешены. Строки/комментарии игнорируются;
проверены отдельными тестами, включая обращение через переменную SceneTree.
Runtime regression запускает настоящую миссию, оставив current_scene чужим
пустым узлом; проверяет стрельбу, гранату, пул следов, команды замены оружия,
новую дверь/мебель из каталога, живущие отдельно обломки и динамических врагов.
Фактические результаты запуска записываются после завершения CI.
