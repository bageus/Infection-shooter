# Размер репозитория: план перехода на Git LFS

Состояние на 05.10.2026: `.git` ≈ 445 МБ, рабочее дерево ≈ 438 МБ
(GLB/FBX ≈ 214 МБ, PNG/JPG ≈ 208 МБ). В истории ≈ 318 МБ удалённых `.blend`.
Каждый клон и каждый CI-прогон скачивает всё это.

## Уже сделано (без переписывания истории)

- Удалены 159 неиспользуемых `models/objects/textures/Image_*.png` (12 МБ).
- Из git убраны сгенерированные файлы (`__pycache__`, отчёт аудита моделей);
  `.gitignore` покрывает сборки, кэш Python, бэкапы Blender.
- `export_presets.cfg` (Windows, Web) не кладёт в сборку исходники врагов
  (`models/objects/characters/enemy/*.glb` и их `*_N.jpg`, ≈ 140 МБ),
  тесты, инструменты, документацию и плагин редактора.
- Дубликаты текстур (59 групп, ≈ 10 МБ) — в основном картинки, которые Godot
  сам извлекает из GLB рядом с моделью; удалять их бессмысленно, импорт
  создаст их снова. Экономия придёт с LFS (одинаковые файлы хранятся один раз).

## Требует решения владельца (необратимо)

Перевод бинарных файлов в LFS **с переписыванием истории** меняет хэши всех
коммитов: все клоны и открытые ветки/PR придётся пересоздать, push только
принудительный. Без переписывания истории (только новые изменения в LFS)
размер `.git` не уменьшится, зато ничего не ломается.

Вариант A — только вперёд (безопасно):

```bash
git lfs install
git lfs track "*.glb" "*.fbx" "*.png" "*.jpg" "*.ogg" "*.blend"
git add .gitattributes && git commit -m "Track binary assets with Git LFS"
git add --renormalize . && git commit -m "Move binary assets to LFS"
git push
```

Вариант B — с переписыванием истории (максимальная экономия, ≈ 400 МБ):

```bash
# сначала закрыть все PR и сделать резервную копию репозитория
git lfs migrate import --everything --include="*.glb,*.fbx,*.png,*.jpg,*.ogg,*.blend"
git push --force --all && git push --force --tags
# всем участникам: заново клонировать репозиторий
```

Квота бесплатного LFS на GitHub — 10 ГБ хранилища и 10 ГБ трафика в месяц
(проверить актуальные лимиты в настройках аккаунта).
